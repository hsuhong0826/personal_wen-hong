# 停車狀態順序異常分析系統

## 📁 檔案結構

```
分析/
│
├── status順序_080508008.csv            # 原始資料
├── status_16種情況判斷規則.csv          # 16 種狀態轉換的判斷規則對照表
│
├── analyze_status.py                   # 分析程式：讀取原始資料，偵測異常與未回傳
├── analyze_result.csv                  # 分析結果輸出（異常 + 可疑筆數）
├── analyze_result_status3.csv          # status=3（未回傳）紀錄輸出
│
├── generate_report.py                  # 報表程式：將分析結果製成 HTML 報表
├── report.html                         # 最終輸出報表（靜態圖表）
│
└── README.md                           # 本說明文件
```

## 📄 原始資料欄位說明（status順序_080508008.csv）

| 欄位 | 說明 |
|------|------|
| `section_id` | 區段 ID |
| `ps_id` | 停車位 ID |
| `vendorcode` | 廠商代碼 |
| `sta_dt` | 狀態發生時間 |
| `status` | 狀態值（1 / 2 / 3 / 5 / 6） |

### status 定義

| 值 | 說明 | 類型 |
|:---:|------|------|
| `1` | 車子**進入** | 即時觸發 |
| `2` | 車子**離開** | 即時觸發 |
| `3` | **設備未回傳** | 異常訊號 |
| `5` | **有車**停放中 | 排程（每 1 小時） |
| `6` | **無車**停放 | 排程（每 1 小時） |

## 🔍 analyze_status.py — 分析程式

### 分析流程

```
讀取 CSV（分批，每批 20 萬筆）
        ↓
將 status=3 的資料另存至 analyze_result_status3.csv（類型：未回傳）
        ↓
剩餘資料依 section_id + ps_id + vendorcode 分組
        ↓
取得每筆的「前一筆狀態」與「前一筆時間」
        ↓
比對 16 種轉換規則 → 判斷 正常 / 可疑 / 異常
        ↓
輸出 analyze_result.csv
```

### 16 種轉換規則

| 前一筆 → 當前 | 判斷 | 說明 |
|:---:|:---:|------|
| 1 → 1 | ❌ 異常 | 連續收到進車事件 |
| 1 → 2 | ⚠️ 可疑 | 車輛進入後直接離開 |
| 1 → 5 | ✅ 正常 | 進入後持續停車 |
| 1 → 6 | ❌ 異常 | 剛進入但排程顯示無車 |
| 2 → 1 | ⚠️ 可疑 | 離開後很快又有車進入 |
| 2 → 2 | ❌ 異常 | 連續收到離開事件 |
| 2 → 5 | ❌ 異常 | 已離開但排程仍顯示有車 |
| 2 → 6 | ✅ 正常 | 離開後排程確認無車 |
| 5 → 1 | ❌ 異常 | 有車格狀態卻又收到進車事件 |
| 5 → 2 | ✅ 正常 | 有車後收到離開事件 |
| 5 → 5 | ✅ 正常 | 持續停車 |
| 5 → 6 | ❌ 異常 | 未收到離開事件就變成無車 |
| 6 → 1 | ✅ 正常 | 無車後有新車進入 |
| 6 → 2 | ❌ 異常 | 無車格卻收到離開事件 |
| 6 → 5 | ❌ 異常 | 未收到進車事件就變成有車 |
| 6 → 6 | ✅ 正常 | 持續無車 |

### 可疑紀錄時間差門檻

| 轉換 | 說明 | 門檻 |
|:---:|------|------|
| 1 → 2 | 進車後直接離開 | 超過 `MIN_TIME_DIFF_1_TO_2` 分鐘才輸出 |
| 2 → 1 | 離開後快速進車 | 超過 `MIN_TIME_DIFF_2_TO_1` 分鐘才輸出 |

### 輸出欄位

#### analyze_result.csv（異常 + 可疑）

| 欄位 | 說明 |
|------|------|
| `section_id` | 區段 ID |
| `ps_id` | 停車位 ID |
| `vendorcode` | 廠商代碼 |
| `前一筆時間` | 前一筆資料的時間戳記 |
| `前一筆狀態` | 前一筆的 status 值 |
| `當前時間` | 當前資料的時間戳記 |
| `當前狀態` | 當前的 status 值 |
| `差異時間` | 兩筆的時間差（分鐘），僅 1→2 / 2→1 有值 |
| `類型` | `異常` 或 `可疑` |
| `說明` | 異常原因文字說明 |

#### analyze_result_status3.csv（未回傳）

| 欄位 | 說明 |
|------|------|
| `section_id` | 區段 ID |
| `ps_id` | 停車位 ID |
| `vendorcode` | 廠商代碼 |
| `sta_dt` | 狀態發生時間 |
| `status` | 固定為 `3` |
| `類型` | 固定為 `未回傳` |
| `說明` | 固定為 `設備未回傳` |

### 效能優化設計

- **分批讀取**：每次讀取 20 萬筆，避免記憶體爆滿
- **跨批次銜接**：每批保留各設備最後一筆作為緩衝，避免批次邊界漏判
- **向量化運算**：使用 `groupby().shift(1)` + 布林遮罩取代逐行迴圈，效能提升約 10~50 倍

## 📊 generate_report.py — 報表程式

### 報表內容

#### 區塊一：總覽統計
- **統計卡片**：原始總筆數、異常筆數（含佔比）、可疑筆數（含佔比）、未回傳筆數（含佔比）、涉及廠商數
- **圓餅圖**：異常 / 可疑 比例
- **統計表**：各類型筆數、佔異常+可疑比例、佔全部原始資料比例

#### 區塊二：依廠商（vendorcode）分類
- **堆疊長條圖**：所有廠商的異常 + 可疑筆數（無資料者顯示 0）
- **明細表**：各廠商可疑筆數（佔可疑總數比例）、異常筆數（佔異常總數比例）、合計，含合計列

#### 區塊三：各廠商未回傳（status=3）統計
- **長條圖**：所有廠商的未回傳筆數（無資料者顯示 0）
- **明細表**：各廠商未回傳筆數與佔未回傳總筆數比例，含合計列

> 廠商清單取異常結果與未回傳結果的聯集，確保所有廠商皆出現在圖表與表格中。

### 技術說明

- 使用 **matplotlib** 繪製圖表並轉為 Base64 圖片嵌入 HTML
- 完全靜態，不需網路連線即可開啟
- 中文使用微軟正黑體字型

### 如何執行

```bash
# 步驟一：執行分析
python analyze_status.py

# 步驟二：產製報表
python generate_report.py

# 開啟報表
# 直接用瀏覽器開啟 report.html
```
